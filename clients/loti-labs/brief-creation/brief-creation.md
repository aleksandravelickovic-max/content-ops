# Loti Labs — Content Brief Guidelines

---

## Setup

- Verify whether python is installed. If it isn't, install it before moving on.
- Read this file: `drafts-local/loti-labs/data-schema.json` (JSON schema for the data file)

## Inputs

Ask the user to provide:
- **Title**
- **Keywords**
- **Link target pages**
- **Comments**
- Anything else useful

## Process

1. Run the full SERP analysis (Step 1 below) before building the outline.
2. Build the outline and fill the JSON data file following the schema in `data-schema.json`.
3. Run `py fill_brief.py <data-file>.json` from the `drafts-local/loti-labs/` directory to generate the `.docx` deliverable in `drafts-local/loti-labs/deliverables/`.
4. Once the `.docx` is confirmed saved, delete the JSON data file.
5. Do not produce a markdown file. The deliverable is always the `.docx` generated by the script.

## Step 1 — SERP Analysis

### 1a — Main agent: initial SERP search

1. Search for the target keyword in the U.S. market.
2. Record the following directly from the search results page:
    - **2026 SERP context:** notable features, AI Overviews, or shifts in how the topic is being handled
    - **People Also Ask questions:** collect all visible PAA questions; these become featured snippet targets
3. Identify the top 10 organic results to analyze and dispatch subagents.

### 1b — Subagent competitor research

Send subagents to fetch and analyze the top 10 ranking pages.

Rules for subagents:
- If a Loti Labs page appears in the results, skip it.
- If a subagent cannot fetch the page content, skip it.
- Aim for 10 analyzed results. When pages are unfetchable, include the next results in the analysis.

Each subagent must return:
- **Word count** of the page
- **Content format** (e.g., listicle, guide, product page, research summary)
- **Domain type** (e.g., supplier, academic, media, ecommerce)
- **Tone** (e.g., scientific, educational, commercial)
- **What the competitor covers well** (topics, structure, depth)
- **Content gaps** — topics missing or underdeveloped relative to the keyword

### 1c — SERP-level synthesis

After subagents return, compile the following:

- **Content type dominating the SERP:** based on content formats reported by subagents
- **Average word count** across the analyzed results
- **Competitor content gaps:** patterns of missing or weak coverage across multiple results
- **Domain types ranking:** based on domain types reported by subagents
- **Tone of ranking content:** based on tones reported by subagents
- **2026 SERP context** from the initial SERP search in step 1a

### Featured snippet targets

Use the PAA questions collected in step 1a as featured snippet targets.

During outline building, assign each PAA question to the body section where it fits most naturally. Cover it there with:
1. A 40–60 word concise answer placed immediately below an H2 or H3
2. An expanded explanation following the concise answer

PAA questions that cannot be assigned to a body section go to the FAQ. Do not assign the same question to both a body section and the FAQ.

## Step 2 — Outline

Build the article outline using the SERP analysis findings.

The final goal is to create an article that is higher quality and more comprehensive than the competitors'.

The outline must:
- Fit a coherent word count based on competitor averages and topic complexity
- Follow a logical, didactic flow
- Cover all critical competitor topics
- Fill the identified competitor gaps
- Avoid repeating information across sections

### Heading rules

- Create a CTR-driven, SEO-oriented H1 title. 
- The number of H2s and H3s is determined by what the topic and competitor landscape require — do not pad or cut artificially.
- When H3s are used under an H2, include a brief introductory sentence or two between the H2 and the first H3.
- Avoid H4s.
- Capitalize H2 and H3 headings following Associated Press style. Exception: FAQ items are H3s, but use sentence case (first letter capitalized only).
- A meaningful heading for the concluding section (after FAQs). Not just "Conclusion".
- No section should exceed 300 words.

### Micro-query rules

Each heading should represent a directly answerable micro-query. Apply these rules:

- The question must be directly answerable (no vague or abstract headings)
- No compound questions; one idea per heading
- The heading must allow a clear first-sentence answer
- Each paragraph answers only one query

### Introduction

The introduction must:
- Include the main keyword in the first or second sentence
- Provide a concise answer to the title question
- Present the scope of the article
- Establish value and context for the reader
- Be 100–150 words across 2–3 paragraphs

### FAQ section

- The FAQ section is placed before the concluding section
- The FAQ covers adjacent questions — closely related to the topic but not the focus of any body section
- Do not place a question in the FAQ if a body section already answers it
- Use PAA questions as the starting point; supplement with other adjacent questions when needed to fill the FAQ

### CTAs (provided by the user)

- Primary target page: a soft CTA placed in the conclusion
- Secondary target page: a soft CTA placed once in the article
- Tertiary target page (when applicable): a soft CTA placed once in the article

### Skimmability elements

- Identify the single best section to place a table. Indicate that in the outline guidance. One table is enough per article, although two are acceptable.
- Identify sections that would benefit from bullet lists. Indicate that in the outline guidance.

### Section guidance

Each section in the `sections` array contains guidance bullets that tell the writer what to cover.

Rules for writing guidance bullets:
- Frame each bullet as a micro-query: a specific question the section must answer
- Do not include statistics, figures, study names, or source claims; leave research to the writer
- Do not prescribe the answer, only the question
- Flag snippet targets as: *Snippet target: [PAA question]*
- Flag table placement as: *Table: [description of what to compare]*
- Flag bullet list placement as: *Bullet list: [what the list should cover]*
