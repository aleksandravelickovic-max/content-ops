Generate a content brief for the ClickUp task below, post it as a comment on the task, and do not output anything else.

## Input

Task ID: $ARGUMENTS

## Step 1 — Read the task

Use `mcp__claude_ai_ClickUp__clickup_get_task` to get the full task details.

Extract:
- Task name — this is the primary keyword or topic
- Task description — check for additional context, target keyword, audience, or constraints
- Assignees — note who it's assigned to

## Step 2 — Check for an existing brief

Use `mcp__claude_ai_ClickUp__clickup_get_task_comments` on the task.

If any comment contains the marker `🤖 Auto-Brief`, stop. Do not generate a duplicate. Report: "Brief already exists on this task."

## Step 3 — Run SERP research (mandatory — do not skip or summarise)

1. Use WebSearch to find the top-ranking pages for the task topic/keyword.
2. Select 3–5 representative results. Exclude ads, duplicate domains, Reddit, Quora, and forum threads.
3. Use WebFetch on each selected result to read the full page content.
4. From the fetched pages, extract:
   - Common H2/H3 patterns across multiple results
   - Definitions used in introductions
   - Questions used in headings
   - Step patterns, comparison patterns, and list structures
   - Sections that appear weak, shallow, or missing across results
5. Identify any genuine gap in the SERP: what do top results fail to cover or cover poorly?
6. If no gap exists, say so explicitly in the Content angle section — do not invent one.

Base the entire brief structure on this live SERP analysis. Do not rely on assumptions or training data.

## Step 4 — Write the brief

Use exactly this 9-section structure. No introductions, no closing notes, no commentary between sections.

---

### 1. Definition-first angle
One sentence. Entity-first. Precise, not generic. Must name the subject directly.

### 2. Search intent breakdown
What the searcher is actually trying to do. Not "informational/commercial" labels — the real job-to-be-done behind the query.

### 3. Content angle
How this article will differ from what is currently ranking. Name the specific gap, contrarian take, or depth advantage identified in the SERP. If no clear differentiator exists, state that directly.

### 4. Proposed structure
H2 and H3 headings only.

Rules:
- Each H2 must reflect a real user query or search pattern observed in the SERP
- Phrase H2s as a searcher would — not as generic labels (e.g., avoid "Benefits", "Overview", "Importance")
- Use H3s only when the H2 covers a multi-part concept requiring breakdown
- Each H3 must be a distinct sub-question, step, or component

Format:
- H2 title
  → mapped query this H2 answers
  - H3 (if needed)
    → mapped sub-query

### 5. Key questions to answer
Specific, answerable questions aligned with AEO/GEO. These are the questions a user would ask an AI answer engine and expect a named source to answer.

### 6. Entity coverage
Core entities — products, people, tools, concepts, related terms — that must appear for topical completeness. One line per entity with a one-line reason for inclusion.

### 7. Practical section
One H2 dedicated to implementation, workflow, tools, or steps. Name specifically what the reader will do or build after reading this article.

### 8. Risks to avoid
What makes content on this specific topic generic, wrong, or low-value. These must be topic-specific traps — not general writing advice.

### 9. Answer surface opportunities
Where this content can appear in AI answers or featured snippets. Identify which of the following apply and why:
- Definition opportunity (first-sentence answer)
- Direct Q&A pairs
- Comparison statements
- Step-by-step instructions
- Table or structured list opportunity

---

## Step 5 — Post the brief as a comment

Use `mcp__claude_ai_ClickUp__clickup_create_task_comment` to post the brief on the task.

Comment format:

```
🤖 Auto-Brief | [task name]

---

[full 9-section brief here]

---
*Generated by Claude Code — based on live SERP analysis. Review and adjust before assigning to writer.*
```

Do not output the brief in the conversation. Confirm only: "Brief posted on [task name] — [task URL]."

## Constraints

- Never invent SERP data. Only use what WebSearch and WebFetch return.
- If WebSearch or WebFetch fails, stop and report the error — do not generate a brief without SERP data.
- Do not add filler sections. If a section cannot be filled with specific, defensible content from the SERP analysis, remove it and note the omission.
- Do not replicate competitor structure. Use SERP patterns to inform decisions, not to copy outlines.
- Use mechanism → capability → outcome hierarchy when describing tools or features.
